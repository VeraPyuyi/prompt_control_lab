# 本地控制 UI

[English](control_ui.en.md) | [控制闭环](control_loop.zh.md) | [控制基准](control_benchmark.zh.md) | [高级诊断](research_from_paper.zh.md)

本地 React 工作台通过受限的本地 FastAPI 服务读取版本化运行产物。它不需要账号，也不是事实源：JSON 与 JSONL 保持权威，UI 只提供复核界面。上一版 Streamlit 界面可通过 `--legacy-streamlit` 继续使用。

```bash
pcl ui --runs runs
pcl ui --runs runs --language zh --legacy-streamlit
```

## 导航

工作流顺序固定，便于操作者从输入到结果复核一次决策：

**变更审查 -> 执行前 -> 运行 -> 原因 -> 执行后 -> 决策 -> 历史 -> 稳定性与可信度**

| 视图 | 用途 |
|---|---|
| **变更审查** | 在一页中查看结论、变更类型、最可能原因、证据覆盖、观察结果和下一步行动。 |
| **执行前** | 在执行前检查提示词、授权级别、模型提供商或 Agent、脱敏状态和预检决策。 |
| **运行中** | 在实时运行或重放期间查看归一化控制事件和有界状态更新。 |
| **原因** | 复核归因证据以及诊断所引用的事件；缺失证据会明确显示。 |
| **执行后** | 对照请求目标、已记录输出和稳定性观测。 |
| **决策** | 查看最终的允许、建议、门控或证据不足决策及其理由。 |
| **历史** | 比较本地版本化运行并打开原始产物。SQLite 可加速列表，但可由 JSON 重建。 |
| **稳定性与可信度** | 用通俗语言查看最终目标影响、局部稳定边界和局部解可信范围；学术名称、原始字段与理论前提放在技术细节中。 |

## 旗舰案例

运行 `pcl ui --runs docs/case_studies --language zh` 后，变更审查首页会显示三张案例卡：**Agent 运行优化**、**模型切换审查**和 **Checkpoint 发布审查**。选择案例后，URL 会记录当前案例，执行前、原因、执行后、决策与稳定性页面也会同步读取同一组嵌套 `review/` 产物。Agent 案例的技术标签仍是 `prompt_change`，产品名称不会把它伪装成两个不同 Agent 身份的比较。

## 复核边界

UI 解释已经记录的证据，不会补造产物中不存在的证据。视觉趋势不是因果证明，绿色决策不是安全证明，稳定性诊断也不是默认控制要求。需要独立复核时，应导出或共享版本化产物。
