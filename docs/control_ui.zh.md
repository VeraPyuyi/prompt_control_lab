# 本地控制 UI

[English](control_ui.en.md) | [控制闭环](control_loop.zh.md) | [控制基准](control_benchmark.zh.md) | [高级诊断](research_from_paper.zh.md)

本地 UI 从磁盘读取版本化运行产物。它不需要账号，也不是事实源：JSON 与 JSONL 保持权威，UI 只提供复核界面。

```bash
pcl ui --runs runs
```

## 导航

工作流顺序固定，便于操作者从输入到结果复核一次决策：

**执行前 -> 运行中 -> 原因 -> 执行后 -> 决策 -> 历史 -> 高级**

| 视图 | 用途 |
|---|---|
| **执行前** | 在执行前检查提示词、授权级别、模型提供商或 Agent、脱敏状态和预检决策。 |
| **运行中** | 在实时运行或重放期间查看归一化控制事件和有界状态更新。 |
| **原因** | 复核归因证据以及诊断所引用的事件；缺失证据会明确显示。 |
| **执行后** | 对照请求目标、已记录输出和稳定性观测。 |
| **决策** | 查看最终的允许、建议、门控或证据不足决策及其理由。 |
| **历史** | 比较本地版本化运行并打开原始产物。SQLite 可加速列表，但可由 JSON 重建。 |
| **高级（Advanced）** | 仅在假设与证据成立时打开可选的 PEOC、soft/hard、trajectory、Riccati 和 `tv-soft` 诊断。 |

## 复核边界

UI 解释已经记录的证据，不会补造产物中不存在的证据。视觉趋势不是因果证明，绿色决策不是安全证明，高级诊断也不是默认控制要求。需要独立复核时，应导出或共享版本化产物。
